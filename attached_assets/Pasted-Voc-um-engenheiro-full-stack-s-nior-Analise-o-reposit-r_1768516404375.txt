A) Corrigir links do roteiro (Winalist / Booking / DiscoverCars)
A1) Winalist — NÃO inventar URL / NÃO usar “/visita/{slug}”

Hoje o sistema está gerando links errados do tipo:

https://www.winalist.pt/visita/adega-mae

Mas o correto (exemplo real) é:

https://www.winalist.pt/hosts/3134/adegamae?utm_source=lisbonwineroutes&utm_medium=affiliate&utm_campaign=lisbonwineroutes

Regra obrigatória (Winalist)

Nunca gerar URL “na unha” por slug ou conversão de nome.

Para links Winalist, o sistema deve usar uma URL real do site (por exemplo, página /hosts/{id}/{slug} ou a URL específica da experiência, caso exista).

Depois de ter uma URL real, apenas anexar/mesclar a UTM:

utm_source=lisbonwineroutes&utm_medium=affiliate&utm_campaign=lisbonwineroutes

Se a URL já tiver querystring, anexar com &....

Se não tiver, anexar com ?....

Implementação: resolver URL real do Winalist

Crie uma camada de resolução com esta ordem de prioridade:

Opção 1 (preferida): catálogo/mapeamento local (mais confiável)

Criar um arquivo/tabela winalist_url_map (JSON/DB) que mapeie ID interno do item (ou nome normalizado + região) → winalistUrl.

Ex.: "adega_mae" -> "https://www.winalist.pt/hosts/3134/adegamae"

No gerador do roteiro, quando o item tiver winalistUrl conhecido, usar essa URL + UTM.

Opção 2: tentativa automatizada (somente se já existir infraestrutura de scraping/lookup)

Se o projeto já tem um mecanismo de busca/lookup, implementar um resolver que:

pesquise no Winalist e recupere a URL oficial do host/experiência

cacheie o resultado no DB para não bater sempre

Importante: se não for possível implementar isso com confiabilidade (por bloqueios/Cloudflare/ausência de API), NÃO forçar.

Fallback obrigatório (quando não conseguir resolver)

Se não houver URL real mapeada e não for possível buscar de forma confiável:

No roteiro/PDF, exibir sem link de Winalist e mostrar um fallback seguro:

Link do Google Maps para o local (nome + endereço), OU

site oficial se existir no dataset

E registrar um log/flag interno tipo missing_winalist_url: true para eu conseguir te entregar a lista depois.

Comportamento esperado (muito importante):

Se não conseguir obter URL real do Winalist com confiança, me avise no output/log que você precisa que eu gere/forneça “a relação de todas as URLs do Winalist” para mapear corretamente.

Função Winalist (obrigatória)

Crie buildWinalistAffiliateUrl(realUrl: string): string

Valida que o domínio é winalist.pt (ou winalist.com se já usado no repo, mas preferir winalist.pt).

NÃO altera path.

Só adiciona/mescla:
utm_source=lisbonwineroutes&utm_medium=affiliate&utm_campaign=lisbonwineroutes

A2) Booking — sempre via AWIN (faltou parâmetro)

Hoje está saindo assim (errado):

https://www.booking.com/hotel/pt/areias-do-seixo.pt-pt.html

O correto (exemplo) é:

https://www.awin1.com/cread.php?awinmid=18120&awinaffid=1914530&ued=https%3A%2F%2Fwww.booking.com%2Fhotel%2Fpt%2Fareias-do-seixo.pt-pt.html

Regra obrigatória (Booking)

Toda URL de Booking deve ser convertida pela função AWIN:

buildBookingAwinUrl(destinationUrl: string, clickref?: string): string

Regras:

base: https://www.awin1.com/cread.php

awinmid=18120

awinaffid=1914530

clickref opcional

ued recebe destinationUrl totalmente URL-encoded

Nunca encode nos params da AWIN, apenas no valor do ued

Integrar essa função:

na UI do roteiro

no gerador do PDF

em qualquer lugar que apareça Booking

Adicionar testes básicos:

booking sem query

booking com query

com clickref e sem clickref
